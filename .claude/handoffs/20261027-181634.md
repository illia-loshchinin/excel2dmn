Current sub-goal, in the user's words: "write good end to end tests to cover camunda 7 and 8 with all possible transformations and use cases", built by agent teams (scenario writer → TDD test writer → fixer), then "go ahead with your suggested answers and review with dedicated agents team for self improvement loop".

## Decisions taken

- **v1 scope:** Camunda 8 output (#12) and feelin 8 (#24) are IN 1.0. Both are merged.
- **E2E setup (user's choices):**
  - 4 teams by area: C7 convert, C8 convert, import and round-trip, CLI/config/init.
  - Fixers fix clear bugs. Behavior changes are marked `it.fails` and raised as questions.
  - Tests run the real CLI, re-parse every DMN, and build workbooks in code.
- **Branch:** merge #24 first, then a new PR on the same branch. That is PR #25.
- **The 10 behavior questions — user approved "go ahead with your suggested answers":**
  1. Two sheets with the same decision id (also after sanitising/case folding): **hard error**, exit 1, message names both sheets; no `.dmn` written for the colliding sheets. `identity.collisionSuffix` stays for ids inside one decision only.
  2. Conversion warnings on **stderr** (already implemented); document the channel and format in README and spec.
  3. `import -o` **creates missing parent dirs**, like convert.
  4. When import auto-switches to the 5-row allowed-values layout, **print a hint** naming `header.allowedValuesOffset 3`, `header.labelOffset 4`, `rules.startOffset 5`.
  5. File-read errors (EISDIR/EACCES/ENOENT) for convert and import inputs **name the path**.
  6. A DMN 1.1/1.2 namespace is **detected and rejected** as not DMN 1.3, naming the path and the version.
  7. `--sheet` **keeps current semantics**: it narrows the sheets already matching "DMN". Update the test, make the error mention it, document it.
  8. Unknown config keys give a **stderr warning** naming the key path; not an error. Watch out for open-ended maps.
  9. `init` **refuses to overwrite** without `--force`.
  10. `init --sheet` **warns** when the converter wouldn't select that name. `config` with non-TTY stdin **keeps** current behavior (writes the defaults plus a stderr note).
- **Review loop design (approved):** after applying the decisions, run rounds of:
  - 4 reviewers, one lens each: correctness, spec/docs, test quality, robustness/security;
  - 1 skeptic per finding, defaulting to refuted;
  - 1 fixer applying the confirmed findings.

  Stop when a round confirms nothing, max 3 rounds. The fixer must not reverse the decisions above.
- Squash-merge is the repo convention. Force-push is blocked by the auto-mode classifier. To restart the branch after a squash-merge, use `git merge -s ours origin/<branch>` and then a normal push.
- Lockfile changes must use npm 11 (`npx -y npm@11 install ...`), because npm 10 crashes with an arborist `edgesOut` bug.
